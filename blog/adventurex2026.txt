<li>我与组委会之间没有签署保密协议，报名条款和隐私政策里也没有约定我负有此类配合义务；而他们要的&quot;私人聊天记录、第三方身份信息&quot;属于受法律保护的通信秘密和个人隐私，其中还涉及不由我单方决定披露的他人信息。<strong>这是隐私边界问题，不是诚意问题</strong>——我愿意澄清，但方式不能是交出私人通讯和别人的身份信息。</li>
</ul>
<p>（我当时的回信原件我保留着，为篇幅这里只摘要点。）</p>

<h2 id="二现场网络二维码和一个开源小工具" class="prose-heading">二、现场：网络、二维码，和一个开源小工具</h2>
<p>进入现场后，签到需要刷一个二维码，走的是他们的 United 登录。但这套系统当时对手机端的适配存在明显问题：部分手机打开时会被安全拦截，导致刷不出二维码，现场因此出现了不少签到卡顿。我后来问及是谁负责这块时，得到的回答是各团队之间互相指向对方，我至今不清楚具体归属。</p>
<p>第一天我做了一个开源小工具来缓解签到问题：拿到链接后直接取出二维码，方便现场使用。整个项目开源，部署在 Cloudflare Worker 上以尽量保证数据不被篡改；有隐私需求的人也可以自行第三方部署。</p>
<div class="callout callout-tip" role="note"><div class="callout-title"><svg class="callout-icon" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="1.6" stroke-linecap="round" stroke-linejoin="round" aria-hidden="true"><path d="M9 18h6M10 22h4M12 2a7 7 0 0 0-4 12.7c.6.5.9 1.1 1 1.8h6c.1-.7.4-1.3 1-1.8A7 7 0 0 0 12 2z"/></svg><span>开源小工具</span></div><div class="callout-body"><p>项目地址：<a href="https://github.com/jiangmuran/advxqr">https://github.com/jiangmuran/advxqr</a>（部署在 Cloudflare Worker，可自行第三方部署）</p>
</div></div><p>让我比较不解的是后续的反应：在&quot;优化手机端体验&quot;和&quot;应对我这个小工具&quot;之间，对方的选择是修改 App ID 让我的二维码逻辑失效、并提醒我不要再做下去；我加了自动适配和匹配逻辑后，对方又给整个流程加上了人机验证。</p>
<p>关于现场网络，我也想客观地补一句：期间还发生过&quot;要求选手关闭个人热点、否则可能影响参赛资格&quot;的情况，理由是热点影响了网络。就我在现场的体验而言，把网络不稳定归因到选手热点，我个人是存疑的，但这只是我的观察，无法证实主办方内部的真实原因。</p>
<p><img src="/blog/adventurex2026/05.png" alt="现场要求选手关闭个人热点、否则可能影响参赛资格的通知（人名已打码）"></p>

<h2 id="三闸机系统这件事的高潮也是我要说得最谨慎的部分" class="prose-heading">三、闸机系统：这件事的高潮，也是我要说得最谨慎的部分</h2>
<p>这一段我会写得很克制，因为它后来被描述成了&quot;我入侵系统&quot;，而我需要把它讲准确。</p>
<p>现场入场用的是一套自助闸机。在使用过程中，我发现它存在明显的安全问题（此处我不展开具体技术细节，以免被他人利用），据我判断，在特定条件下可以在未经充分鉴权的情况下接触到设备的部分权限。<strong>发现之后，我第一时间把情况告知了赛事方。</strong></p>
<p>之后，出于把问题修好的想法，我花了一个通宵研究，写出了一版做了 UI 优化、修了不少 bug、并<strong>修补了我发现的安全问题</strong>的改进程序。为了不影响现有流程，我让它完全兼容他们原有的二维码与鉴权体系——旧二维码照常可用。</p>
<div class="callout callout-warning" role="note"><div class="callout-title"><svg class="callout-icon" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="1.6" stroke-linecap="round" stroke-linejoin="round" aria-hidden="true"><path d="M12 9v4M12 17h.01M10.3 3.9 1.8 18a2 2 0 0 0 1.7 3h17a2 2 0 0 0 1.7-3L13.7 3.9a2 2 0 0 0-3.4 0z"/></svg><span>关键的一点，我要说清楚</span></div><div class="callout-body"><p>天亮后，<strong>他们闸机软件的开发者来到现场，在他全程注视、没有提出反对的情况下</strong>，我向他演示并讲解了整套改动的工作流程，并把它部署到了现场闸机上，运行正常。我也<strong>第一时间把后台连接信息同步给了场地方一份</strong>，验证没有问题后我们才继续。我自始至终愿意、也主动表示可以交出全部源码。</p>
</div></div><p>到了早上，情况发生了变化。他们团队内部似乎出现了分歧，有成员强硬要求直接给闸机断电，理由是我&quot;私自修改了系统&quot;。让我最难受的不是断电本身，而是<strong>从头到尾没有一个人正式和我沟通</strong>——我人就在现场，我一直愿意交出源码、愿意配合恢复，但换来的是一整个上午的人工检票，一晚上的成果就这样作废。期间还有一位自称现场负责人的成员对我说了相当激烈的话（有录音）。当我问对方这些话是否代表团队立场时，得到的是肯定的回答；但事后我再与团队沟通时，又被告知那些话&quot;不代表个人/团队&quot;。到底哪个算数，我至今没有答案。</p>
<p>我想强调两件事实：</p>
<ol>
<li><strong>在他们自己也承认&quot;我的操作并没有真正影响系统&quot;的前提下</strong>，这件事却被描述成了严重事件。据我理解，被反复提及的一个点是：我在代码里写了一行小彩蛋——<strong>只有当刷入的二维码姓名是我自己时</strong>，才会把背景换成一张原神图，我还把这个彩蛋发到了我们的小群里。就是这样一个只对我本人生效的玩笑，被解读成了&quot;系统被入侵、可能引发大规模骚乱&quot;。</li>
<li>因为信息在传递中一再失真，设备提供方一度以为是我&quot;入侵&quot;导致系统瘫痪，于是报了警。<strong>而&quot;我的操作导致系统瘫痪一上午&quot;这个说法，无论从哪个角度都不成立</strong>——这一点我这边有录音佐证。</li>
</ol>
<p>好在当时我们大体达成了和解，警方了解情况后离开，我也继续参赛。（关于为什么这件事会被看得这么重，我个人有一些猜测，但因为无法证实，我把它留作疑问，不写成结论。）</p>

<h2 id="七关于quotddosquot" class="prose-heading">七、关于&quot;DDoS&quot;</h2>
<p>活动期间及之后，主办方对外表示网络服务遭到恶意 DDoS 攻击、造成较大经济损失，并据此报案、征集线索。</p>
<p>我想非常谨慎地说明两点，且<strong>都标注清楚可信度</strong>：</p>
<div class="callout callout-warning" role="note"><div class="callout-title"><svg class="callout-icon" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="1.6" stroke-linecap="round" stroke-linejoin="round" aria-hidden="true"><path d="M12 9v4M12 17h.01M10.3 3.9 1.8 18a2 2 0 0 0 1.7 3h17a2 2 0 0 0 1.7-3L13.7 3.9a2 2 0 0 0-3.4 0z"/></svg><span>两点，分开说，各自标注可信度</span></div><div class="callout-body"><ul>
<li><strong>对于官方公告本身，我不做真假判断</strong>——我没有能力也没有证据去核实攻击是否存在。</li>
<li>但就我个人在现场的观察与理解，全场馆的访问很可能共用少数几个出口 IP，这种情况下如果限流阈值设置不当，正常访问也可能瞬间&quot;打满&quot;、造成网站无法访问。<strong>这只是我基于常识的一种可能性推测，不是对官方结论的否定。</strong> 至于&quot;去年也发生过类似情况&quot;，那属于我听来的说法，我无法证实，请读者仅作为传闻看待。</li>
</ul>
</div></div><p>我把这两点分开写，是因为我不想用一句听起来很确定的话，去替代一件我其实无法证实的事。</p>

<h2 id="八最后我想说的" class="prose-heading">八、最后，我想说的</h2>
<p>写到这里，我其实没有一点&quot;赢了&quot;的痛快。</p>
<p>我一开始是真的很喜欢 AdventureX。我自费做周边、熬夜写工具、在凌晨两点去研究怎么把一个有问题的系统修好——不是因为我想惹事，而是因为我把它当成了一个值得投入的地方。正因为如此，当我发现自己最后被描述成&quot;入侵系统的人&quot;、当我的身份证号出现在一封我从未预料的律师函里时，那种感觉不是愤怒能概括的，更多的是失望。</p>
<p>我写这篇文章，是为了自保，也是为了澄清——我不希望关于我的、不准确的说法继续传下去，更不希望我的身份信息继续在某些地方流转。</p>
